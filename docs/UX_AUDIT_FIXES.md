# UX/UI: виправлення з аудиту

## Топ-5 (критичні)

### Контекст

5 серпня 2026 було проведено аудит UX/UI застосунку (публічна частина + адмін-панель) —
44 знахідки з посиланнями на конкретний код, опубліковані як окремий артефакт. Користувач обрав
топ-5 найпріоритетніших для реалізації. На уточнення щодо поведінки рерандомайзера жеребкування
при вже завершених (COMPLETED) матчах користувач обрав **"Дозволити, але з посиленим
підтвердженням"** замість повного блокування.

### 1. Рерандомайзер: підтвердження при втраті завершених матчів

**Проблема:** `commitDoublesMatchesAction`, `commitSinglesRoundRobinAction`,
`commitSinglesGroupsAction` (`src/lib/actions/matches.ts`) видаляють усі матчі турніру перед
новою жеребкуванням — включно з COMPLETED матчами із зафіксованим рахунком. Діалог показував лише
загальний текст-попередження незалежно від того, скільки саме буде втрачено.

**Рішення:**
- Сервер: усі три commit-екшени отримали параметр `acknowledgedCompletedLoss: boolean` і
  перевіряють `prisma.match.count({ where: { tournamentId, status: "COMPLETED" } })` — якщо
  завершені матчі є і підтвердження не передано, повертають помилку без запуску транзакції
  (захист другого рівня — клієнт уже блокує кнопку, але Server Action доступний і напряму POST-ом).
- Клієнт (`randomize-matches-button.tsx`, `singles-randomize-button.tsx`): коли в турнірі є
  завершені матчі, діалог показує їх точну кількість і вимагає ввести слово **ВИДАЛИТИ** в поле
  підтвердження, перш ніж кнопка запуску жеребкування стане активною. Якщо завершених матчів
  немає — флоу лишається таким, яким був.

### 2. Підтвердження при підвищенні до ADMIN

**Проблема:** `UserRoleSelect` викликав `updateUserRoleAction` одразу при виборі ролі в
випадаючому списку — без підтвердження і без toast про успіх, хоча всі інші небезпечні дії в
адмінці (видалення турніру/матчу/гравця/новини) захищені `AlertDialog`.

**Рішення:** зміна ролі на ADMIN тепер відкриває `AlertDialog` з іменем користувача й описом
наслідків; підтвердження викликає дію. Зниження ADMIN → MEMBER підтвердження не потребує (це не
ескалація прав). Додано `toast.success` після успішної зміни ролі.

### 3. Мобільна навігація: брейкпоінт і touch-target

**Проблема:** повне меню сайту з'являлось лише від 1280px (`xl:`), а тригер мобільного меню мав
розмір лише 28px — менше рекомендованого мінімуму touch-target (~44px).

**Рішення** (`src/components/nav.tsx`): поріг появи інлайн-меню й тригера гамбургера понижено до
1024px (`lg:`). Бейдж "Адмін" навмисно лишено на порозі 1280px (`xl:`) — саме він, за наявним у
коді коментарем, спричиняв переповнення рядка на межі брейкпоінту для довгих імен адмінів; лишаючи
його прихованим у діапазоні 1024–1279px, ризик переповнення не повертається. Тригер гамбургера
збільшено до 44px (`size-11`).

### 4. Закріплена перша колонка в таблицях рейтингу

**Проблема:** таблиці лідерборду, рейтингу (обидві) і турнірної таблиці прокручувались
горизонтально на мобільному без закріпленого імені гравця — прокрутка вправо зносила ім'я з
екрана.

**Рішення:** застосовано патерн, який уже використовувався для матриці особистих зустрічей
(`sticky left-0 z-10 bg-card`) до першої колонки (`TableHead` і `TableCell`) в
`src/app/leaderboard/page.tsx`, `src/app/rating/page.tsx` (обидві таблиці) і
`src/components/tournament-standings.tsx`. Оскільки рядки цих таблиць мають умовний фон (підсвітка
власного рядка/переможця) і `hover:` ефект від `TableRow`, фон закріпленої комірки повторює той
самий умовний вираз, що й фон рядка, плюс `group`/`group-hover` для коректного hover-стану.

### 5. Пошук в адмінці

**Проблема:** список матчів турніру (до сотень рядків для round-robin) не мав фільтра/пошуку;
пікери гравців/акаунтів (`link-player-control.tsx`, `tournament-roster.tsx`) не мали пошуку в
Select з потенційно довгим списком кандидатів клубу.

**Рішення:**
- `tournament-matches.tsx`: клієнтський пошук за іменем гравця + фільтр статусу
  (Заплановані/Завершені/Усі), той самий патерн `useState` + `.filter()`, що вже в
  `players-table.tsx`/`tournaments-table.tsx`. Статуси задані локальною константою, а не
  імпортом значення з `lib/queries/matches.ts` — той модуль тягне Prisma, і імпорт звідти
  значення (не типу) в `"use client"`-компонент зламав би клієнтський бандл (див. нижче).
- `select.tsx`: `SelectContent` отримав необов'язковий пропс `searchSlot` — довільний вузол,
  що рендериться над списком айтемів усередині popup. За замовчуванням `undefined`, тож жоден
  інший виклик `SelectContent` у застосунку не змінився.
- `link-player-control.tsx` і `tournament-roster.tsx`: локальний пошуковий `Input` через
  `searchSlot`, фільтрація кандидатів/гравців перед рендером `SelectItem`.

### Знайдений під час перевірки бо́рдер-кейс

Під час ручної перевірки в браузері виявилось, що `import { MATCH_STATUS_FILTER_VALUES } from
"@/lib/queries/matches"` (значення, не тип) у `"use client"`-компоненті `tournament-matches.tsx`
ламав клієнтський білд: `lib/queries/matches.ts` імпортує `prisma`, і Next.js намагався включити
весь Prisma runtime у браузерний бандл ("the chunking context does not support external modules
(request: node:module)"). Виправлено заміною на локально продубльовану константу — той самий
підхід, що вже застосований у `matches-filters.tsx` для тих самих значень статусу.

### Верифікація

`npm run lint`, `npx tsc --noEmit`, `npm run test` (262 тести) — усе проходить. Ручна перевірка в
браузері через Playwright (тестовий адмін-логін `/api/test-login`): брейкпоінти навбару на
1000/1024/1279/1280/1440px, sticky-колонка на лідерборді й рейтингу при горизонтальній прокрутці
на ширині 390px, діалог підтвердження підвищення ролі, діалог рандомайзера без завершених матчів.

## "Суттєві" (11 пунктів)

### Контекст

Продовження того самого аудиту — секція "Суттєві" повністю, за одним запитом користувача. Пункт
1 користувач переформулював порівняно з оригінальним текстом аудиту (там пропонувалось прибрати
"Gold/Silver", тут — навпаки, уніфікувати всюди до цього варіанту); реалізовано за новим
формулюванням.

### 1. Уніфікація "Gold (сіяні)" / "Silver (несіяні)"

`SINGLES_GROUP_LABEL` (`src/lib/randomize-pairs.ts`) — не просто текст, а значення, яке реально
записується в `Match.round` при жеребкуванні "сіяні проти сіяних". У проді вже є завершені
турніри зі старим значенням ("Сіяні"/"Несіяні") в цій колонці. Замість БД-міграції заради суто
текстового вирівнювання: константу оновлено на нові значення (нові матчі одразу коректні), а
`match-summary.tsx` нормалізує старі значення на рівні відображення (`normalizeRoundLabel`) —
показує однаковий текст і для старих, і для нових матчів, не чіпаючи БД.

### 2-3. Уніфікація фільтрів-пілюль + підписи на лідерборді

Патерн "сегмент-контрол" (`flex gap-1 rounded-lg bg-muted p-1` + активний/неактивний лінк) був
вручну продубльований 5 разів у двох файлах, і саме ця розбіжність спричиняла знахідку #2
(MODEL_FILTERS на `/rating` виглядали як кольорові Badge-посилання, не як таби). Винесено у
`src/components/pill-filter.tsx` (`PillFilterGroup`/`PillFilterLink`), усі місця використання в
`rating/page.tsx` і `leaderboard/page.tsx` переведено на нього. Заразом додано підписи
"Формат:"/"Стать:"/"Рік:" перед рядками фільтрів лідерборду (`leaderboard/page.tsx`), за
патерном "Метод:" з `/rating`.

### 4. Тач-доступні графіки рейтингу

Обидва графіки були в Server Component-файлах з нативним `title`-тултипом (не працює на дотик).
- `RatingHistoryChart` (`src/app/players/[id]/page.tsx` → виніс у
  `src/components/rating-history-chart.tsx`, `"use client"`): тап по точці (через прозоре
  збільшене хіт-коло) показує дату/рейтинг під графіком; `RatingCard` переструктуровано так, щоб
  `<Link>` обгортав лише верхню частину картки (назва/рейтинг/Set Club очки), а графік був поза
  ним — раніше тап по графіку просто вів на `/rating`.
- `RatingDistribution` (`src/app/rating/page.tsx` → `src/components/rating-distribution-chart.tsx`,
  `"use client"`): крапки стали `<button>`, тап показує підказку-бабл над обраною крапкою.

### 5. Групування матчів по днях зі sticky-заголовками

`src/app/matches/page.tsx` — локальна `groupMatchesByDay` (лінійний прохід по вже
відсортованому `getMatchesPage`, ключ дня — `formatDateUTC(scheduledDate ?? createdAt)`, той
самий фолбек, що й `matchDayFilter`). Заголовок групи — день тижня + дата
(`Intl.DateTimeFormat("uk-UA", { weekday: "long", timeZone: "UTC" })`), `sticky top-0`,
рендериться лише коли груп більше однієї.

### 6. "На головну" на сторінках помилок

`error.tsx` — `<Button variant="outline" render={<Link href="/" />}>` поруч з "Спробувати ще
раз". `global-error.tsx` — тут `next/link` не працює (файл поза деревом App Router), тож плейн
`<a href="/">` з `color: inherit` — не потребує окремого dark-override, вже підхоплює наявне
правило кольору тексту.

### 7. Кар'юсель "Останні результати": стрілки та подвійний fade

Секцію винесено в `src/components/results-carousel.tsx` (`"use client"`, приймає вже завантажені
`matches` як проп). Лівий/правий fade-градієнти показуються/ховаються за позицією скролу
(`onScroll`), додано дві маленькі кнопки-стрілки (`scrollBy` з `behavior: "smooth"`), теж
зникають/деактивуються на краях списку.

### 8. Сторінки окремих новин + обрізане прев'ю

`getNewsPostById` (`src/lib/queries/news.ts`) — додано `include: newsPostInclude` (раніше не
підвантажував автора). Новий `src/app/news/[id]/page.tsx` — повний текст, `notFound()` для
неіснуючого id. `news/page.tsx` і головна (`page.tsx`) — заголовок картки тепер лінк на
`/news/[id]`, тіло — `line-clamp-4` замість повного рендеру.

### 9. Theme color для темної теми (PWA/статус-бар)

`src/app/layout.tsx` — `viewport.themeColor` тепер медіа-масив (light: `#3f7a5c`, dark:
`#0a0a0a`, те саме значення, що й dark-фон у `globals.css`/`global-error.tsx`). Це стежить за
системною темою ОС, не за ручним перемикачем застосунку (localStorage) — статичний meta-тег
браузер оцінює сам, до будь-якого JS застосунку, тож слідувати саме ручному вибору він не може.
`manifest.ts`'s `background_color` лишився як є — формат маніфесту не підтримує умовні значення.

### 10. "Скинути фільтри" як кнопка з іконкою

`src/components/matches-filters.tsx` — plain текстовий `<button>` замінено на
`<Button variant="ghost" size="sm"><XIcon /> Скинути фільтри</Button>`.

### 11. Контраст аутсайдера в PredictionBar

`src/components/match-summary.tsx` — `text-muted-foreground` → `text-foreground` для відсоткового
тексту аутсайдера (той самий бар, фаворит уже домінує суцільною заливкою `bg-primary`).

### Верифікація

`npm run lint`, `npx tsc --noEmit`, `npm run test` (262 тести), `npm run build` — усе проходить.
Ручна перевірка в браузері через Playwright: фільтри `/rating` і `/leaderboard` (єдиний вигляд,
підписи), тап по графіках на `/players/[id]` і `/rating` (значення показується, навігація не
спрацьовує), групування `/matches` по днях, кар'юсель на головній (стрілки з'являються/зникають
на краях), перехід з обрізаного прев'ю новини на `/news/[id]`, кнопка скидання фільтрів на
`/matches`.

## "Дрібні / полірування" (10 пунктів)

### Контекст

Остання секція того самого аудиту. Перед реалізацією окремо обговорили пункт "Пояснювальні блоки
рейтингу згорнуті без підказки" — замість розгортати весь блок FAQ чи виносити конкретну секцію
нагору для всіх, зійшлися на точковому рішенні: розгортати автоматично лише секцію "Чому мене
немає в таблиці", і лише для залогіненого глядача, чийого профілю справді немає в поточній
таблиці рейтингу.

Один пункт зі списку ("Картка рейтингу гравця — суцільна лінк-область поверх графіка") на момент
цього запиту вже був вирішений у секції "Суттєві" вище (п. 4) — окремо не чіпали.

### 1. Контекстне розгортання інформера "Чому мене немає в таблиці"

`src/app/rating/page.tsx` — обчислюється `viewerMissingFromTable` (залогінений `viewerPlayer`
є, але його немає серед `rows` поточного формату/методу рейтингу); якщо `true`, саме ця секція
`<details>` рендериться з `open`, решта інформерів лишаються згорнутими як і були.

### 2. Шрифт підписів місяців на графіку активності

`src/app/leaderboard/page.tsx` — `text-[0.65rem]` (10.4px) → `text-xs` (12px) для підписів під
стовпчиками `MonthlyBarChart`.

### 3. Висота смуги "% перемог"

`src/app/leaderboard/page.tsx` — `h-1.5` → `h-2` для прогрес-бару відсотка перемог у таблиці.

### 4. Спільний `RANK_STYLE`

Ідентичний масив кольорів медальних місць, що дублювався в `leaderboard/page.tsx` і
`rating/page.tsx`, винесено в `src/lib/rank-style.ts`; обидва файли тепер імпортують його.

### 5. Кольоровий акцент перемог/поразок у StatCard

`src/components/stat-card.tsx` — новий необов'язковий проп `tone?: "positive" | "negative"`
(`text-primary`/`text-destructive`, той самий колірний код, що й бейджі перемоги/поразки в
`MatchSummary`). Застосовано в `players/[id]/page.tsx` до карток "Перемог"/"Поразок"; нейтральні
картки (матчі, % перемог) тону не отримали.

### 6. Видимий підпис "Дата:" у фільтрі матчів

`src/components/matches-filters.tsx` — поле дати обгорнуто в `<Label htmlFor=...>Дата:</Label>` +
`<Input id=...>` замість самого лише `aria-label`.

### 7. Скорочені картки на головній

`src/app/page.tsx` — три картки ("Турніри", "Статистика клубу", "Гравці") мали по два речення
однакової ваги (`CardDescription` + `CardContent`); об'єднано в один `CardDescription` на картку,
`CardContent` для цих трьох прибрано.

### 8. Порожній стан пошуку показує запит

`src/app/players/page.tsx`, `src/app/tournaments/page.tsx` — "Нічого не знайдено за цим запитом."
→ "Нічого не знайдено за запитом «{query}»." (текст запиту вже екранується React'ом як звичайний
текстовий вузол).

### 9. Maskable-варіант іконок PWA

`src/app/manifest.ts` — додано по одному додатковому запису на кожен розмір з
`purpose: "maskable"` (той самий файл іконки — `brandIconElement` вже full-bleed з центрованим
текстом, безпечний для Android-маски без перемальовування). Next-типи не приймають
спецификаційний рядок `"any maskable"` в одному записі, тож зроблено окремими записами.

### 10. Уніфікація порожніх станів фільтрів

`src/app/leaderboard/page.tsx` ("Немає гравців з такими матчами." → "Немає гравців за цим
фільтром.") і `src/app/matches/page.tsx` ("Матчів ще немає." → "Ще немає жодного матчу.") —
приведено до того самого патерна, що вже був у `tournaments/page.tsx`/`players/page.tsx`.

### Верифікація

`npm run lint`, `npx tsc --noEmit`, `npm run test` (262 тести), `npm run build` — усе проходить.
Ручна перевірка в браузері: кольорові StatCard на профілі гравця, підписи місяців і товща смуга
на `/leaderboard`, видимий підпис "Дата:" на `/matches`, ехо пошукового запиту на порожньому
результаті `/players`, спрощені картки на головній.

## Адмінка — "Суттєві" (11 пунктів)

### Контекст

Секція "Суттєві" з того самого аудиту, цього разу для адмін-панелі. З 12 надісланих пунктів один
("Вибір гравця/акаунту — без пошуку") виявився вже реалізованим у першому раунді (`searchSlot` у
`link-player-control.tsx`/`tournament-roster.tsx`) — пропущено. Три пункти (сортування/фільтр у
таблицях, консистентна пагінація, справжні лінки в рядках) стосувались однієї таблиці турнірів і
реалізовані як один узгоджений редизайн, а не три несумісні патчі поспіль.

### 1. Індикатор активної сторінки в адмін-навігації

`src/app/admin/layout.tsx` був Server Component з nav-смугою прямо в JSX — активний пункт винесено
в новий `src/components/admin/admin-nav.tsx` (`"use client"`, `usePathname()`), решта layout
лишилась серверною. `aria-current="page"` + `border-b-2 border-primary` на активному пункті;
`/admin` матчиться точно (не `startsWith`), решта — префіксом, щоб вкладені сторінки на кшталт
`/admin/tournaments/[id]` теж підсвічували "Турніри".

### 2. Підтвердження видалення учасника з ростера

`RemoveParticipantButton` (`tournament-roster.tsx`) викликав `removeParticipantAction` напряму по
кліку. `removeParticipantAction` — не formData-екшн (плоскі аргументи), тож замість
`useActionState`+`<form>`-патерну (як у `delete-match-button.tsx`) наявний `startTransition`-виклик
обгорнуто в `AlertDialog` із тим самим легким текстом підтвердження.

### 3. Кнопка "Пропустити" в анімації жеребкування

`randomize-matches-button.tsx` і `singles-randomize-button.tsx` — обидва мають `useEffect`, що по
таймеру нарощує `revealedCount` до цілі. У фазі "drawing" (де кнопок не було) додано "Пропустити" →
`setRevealedCount(<ціль>)`; наявний ефект сам коректно переходить у "committing", без змін логіки.

### 4. Помилки форм прив'язані до поля

Новий `src/lib/zod-errors.ts` (`fieldErrorsFromZod`) мапить `ZodError.issues` у
`Record<шлях, повідомлення>`. `ActionState` у `tournaments.ts`/`players.ts`/`matches.ts` отримав
`fieldErrors?: Record<string, string>`. `tournament-form.tsx` (name/дати/формат),
`player-dialog.tsx` (name/email) — `aria-invalid` + текст під полем. `score-dialog.tsx`: рахунок
серіалізується в один `setsJson`, тож шлях Zod — `sets.<індекс>.sideAGames`/`tiebreakSideAPoints`;
знаходимо індекс рядка з ключа помилки й підсвічуємо саме той рядок сітки, а не всю форму.

### 5. Доступний стан перемикача переможця при знятті

`score-dialog.tsx` — двом кнопкам "перемога A"/"перемога B" додано `aria-pressed` +
`role="group" aria-labelledby`.

### 6. Таблиця турнірів: сортування, пагінація, справжні лінки в рядках

Раніше `router.push` в `onClick` рядка (`clickable-table-row.tsx`) — з явним коментарем, чому туди
не поставили "розтягнутий" `<Link>` (в деяких браузерах `position: relative` на `<tr>`/`<td>`
ненадійно створює containing block, лінк "втікає" і перекриває всю таблицю). Замість цього кожна
комірка тепер має власний `<Link>` (`p-0` на `TableCell`, падінг на самому лінку) — справжні `<a>`,
ctrl/cmd/середній клік працює скрізь, без жодного `position`-трюку. `ClickableTableRow` після цього
не мав жодного споживача — видалено. Пагінація: адмінська сторінка перейшла з `getTournaments()`
(без ліміту) на вже наявний `getTournamentsPage` + `PAGE_SIZE=20` + `LoadMore`, пошук — на URL
`?q=` через наявний `SearchInput`. Сортування: `getTournamentsPage` отримав третій параметр `sort`
(`{ key: "startDate"|"participants"|"matches", dir }`), заголовки "Дати"/"Учасників"/"Матчів" —
лінки, що перемикають `?sort=&dir=`. `TournamentsTable` після цього не має локального стану й стала
Server Component.

**Побічний баг, знайдений і виправлений під час перевірки:** `SearchInput` (спільний компонент,
уже використовувався на публічних `/players`/`/tournaments`) після монтування завжди робив
`router.replace(pathname)` через 300мс — навіть якщо користувач нічого не вводив. На публічних
сторінках це непомітно (там більше нема інших query-параметрів), але на адмінській сторінці
турнірів цей виклик скидав щойно застосований `?sort=`/`?dir=` одразу після їх встановлення.
Виправлено: ефект тепер (а) не спрацьовує, якщо значення поля насправді не змінилось відносно
`defaultValue` (покриває сам момент монтування), і (б) коли таки спрацьовує — читає поточні
`useSearchParams()` і змінює лише `q`, зберігаючи решту параметрів замість `router.replace(pathname)`.

### 7. Прев'ю-блокування видалення гравця

`getPlayers()`/`getPlayersPage()` (`queries/players.ts`) отримали
`_count: { matchAppearances, tournamentEntries }`. `DeletePlayerButton` — новий проп `hasHistory`,
`disabled`+`title` на тригері, той самий патерн, що вже в `randomize-matches-button.tsx`.

### 8. Блокування зміни формату турніру видно заздалегідь

`TournamentFormProps` отримав `_count: { matches: number }` (дані вже підвантажені на сторінці,
просто не прокинуті у форму). Select формату — `disabled` + `title`-пояснення, коли
`tournament._count.matches > 0`.

### 9. Пагінація списку новин в адмінці

`admin/news/page.tsx` перейшов з `getNewsPosts()` (без ліміту) на вже наявний
`getNewsPostsPage(limit)` + `PAGE_SIZE=20` + `LoadMore` — той самий патерн, що вже в Users/Audit.

### 10. Фільтр за автором/типом дії в журналі аудиту

`getAuditLogPage` отримав `filter: { actorLabel?, action? }`; новий `getDistinctAuditActors()` —
список акторів для випадаючого списку. Новий `src/components/admin/audit-filters.tsx` — два
`Select` + URL-параметри `?actor=&action=`, той самий каркас, що й `matches-filters.tsx`.

**Побічний баг, знайдений і виправлений під час перевірки:** `AUDIT_ACTIONS`/`AUDIT_ACTION_LABEL`
раніше жили прямо в `src/lib/audit.ts`, який імпортує `prisma`. Імпорт цих констант (значень, не
типів) у клієнтський `audit-filters.tsx` тягнув увесь Prisma runtime у браузерний бандл і ламав
збірку — той самий клас бага, що вже траплявся з `MATCH_STATUS_FILTER_VALUES`. Виправлено виносом
констант у новий `src/lib/audit-actions.ts` без жодного імпорту Prisma; `audit.ts` тепер імпортує
й реекспортує звідти для власного використання (`logAudit`).

### Верифікація

`npm run lint`, `npx tsc --noEmit`, `npm run test` (262 тести), `npm run build` — усе проходить.
Ручна перевірка в браузері через Playwright (тестовий адмін-логін): активний пункт навігації на
вкладеній сторінці турніру, підтвердження видалення учасника, сортування таблиці турнірів у обидва
боки з коректним порядком (перевірено через реальний DOM-порядок рядків, не тільки URL), пошук зі
збереженням активного сортування й коректним очищенням, справжні `<a>` в кожній комірці рядка.

Під час перевірки в headless Chromium (Playwright) React повідомляв про hydration mismatch на
`caret-color: transparent` для деяких `<input>`, включно з `type="hidden"` — де caret-color
об'єктивно не може мати жодного ефекту. Пошук цього рядка по всьому власному коду і по пакету
`@base-ui/react` нічого не знайшов: ця стилізація не походить з коду застосунку. Це узгоджується з
власним поясненням React-попередження ("може статись, якщо в клієнта встановлено розширення
браузера, яке втручається в HTML до завантаження React") — найімовірніше, артефакт середовища
автоматизованого тестування (headless Chromium/Playwright), а не реальний баг застосунку. Зміни в
код не вносились.

## Раунд 2: повторний аудит (24 знахідки)

### Контекст

5 серпня 2026 проведено повторний UX/UI-аудит — читання коду публічної частини й адмін-панелі
окремими прохідками (щоб знахідки одного розділу не тягнули упередження з іншого) плюс ручна
перевірка в реальному Chromium через Playwright на 1440px і 390px, опубліковані як окремий
артефакт (24 знахідки: 2 критичні, 15 суттєвих, 7 дрібних). За запитом користувача реалізовано
все без винятку, одним заходом.

### Публічна частина

**1. Мобільний хедер: перемикачі накладались на назву сайту.** `src/components/nav.tsx` — права
група (`ThemeToggle`/`BackgroundToggle`/гамбургер/кнопка входу) була `shrink-0` в одному рядку з
лого; на 390px сумарна ширина не влазила, елементи фізично перекривались. Прибрано `shrink-0`,
додано `flex-wrap justify-end` — група тепер переноситься на другий рядок замість накладання,
жодної функціональності не втрачено (обидва перемикачі лишились видимими на мобільному).

**2. Активна сторінка в головній навігації.** Раніше показувала лише нейтральний список посилань.
Новий `src/components/nav-links.tsx` (`"use client"`, `usePathname`) — той самий `aria-current`
патерн, що вже в `admin-nav.tsx`, застосовано і до інлайн-рядка (`lg:flex`), і до пунктів у
мобільному dropdown, з одного спільного джерела активного стану.

**3. Сторінки деталей без власного заголовка вкладки.** `news/[id]`, `tournaments/[id]`,
`players/[id]` отримали `generateMetadata` (назва посту/турніру/гравця замість загальної назви
сайту в заголовку вкладки — підтверджено `page.title()` в Playwright).

**4. Непослідовне форматування дат.** `match-summary.tsx` (дата запланованого матчу),
`news/page.tsx`, `news/[id]/page.tsx`, `tournaments/[id]/page.tsx`, `app/page.tsx` (стрічка
новин) — усі раніше викликали `toLocaleDateString("uk-UA")` напряму, тепер `formatDateUTC`, як і
решта застосунку. Час завершення матчу (`toLocaleTimeString`) навмисно не займали — це час доби,
а не календарна дата, інша природа даних.

**5. Пошук у публічних селектах гравця/суперника.** `matches-filters.tsx` (фільтр за гравцем),
`opponent-filter.tsx` — той самий `searchSlot`-патерн з адмінських пікерів (локальний `search`
стейт, фільтрація списку, скидання пошуку на `onOpenChange`).

**6. Контраст тексту на екрані критичної помилки.** `global-error.tsx` — `#6b7280` (≈3.2:1 на
білому) → `#52525b` (≈7.8:1). Темна тема не постраждала: `html.dark body {...!important}` уже
перекриває цей інлайн-колір.

**7. `<th scope="row">` для імені гравця в таблицях.** Новий `TableRowHeader` у
`src/components/ui/table.tsx` (той самий вигляд, що й `TableCell`, але семантичний рядковий
заголовок) — застосовано в `leaderboard/page.tsx` (основна таблиця й матриця "хто кого
обігравав", де він і найпотрібніший), `rating/page.tsx` (обидва блоки), `tournament-standings.tsx`.

**8. Імена в парі переносились суцільним текстом на вузьких екранах.** `match-summary.tsx` —
`SideNames` раніше з'єднувала двох гравців через `" / "` в одному інлайновому потоці; тепер кожен
партнер — окремий блок у `flex flex-col` (той самий принцип, що вже застосований до `ResultTile`
на головній), без " / " — і ранг завжди лишається біля свого гравця.

**9. Текст сторінки входу перебільшував, що потребує авторизації.** `login/page.tsx` і картка
"Гравці" на головній стверджували, що вхід потрібен для перегляду турнірів/статистики/профілів —
насправді все це відкрито без входу (перевірено в браузері). Переформульовано на те, що вхід
реально робить: прив'язує акаунт до профілю гравця.

**10. Висота фільтр-селектів нижче touch-target.** `ui/select.tsx` — новий розмір `size="lg"`
(`data-[size=lg]:h-11`, 44px) як необов'язковий опт-ін, не змінює жоден інший виклик `Select` за
замовчуванням; застосовано до трьох публічних фільтрів (`matches-filters.tsx` ×2,
`opponent-filter.tsx`).

**11. `FORMAT_FILTERS` без `as const`.** `rating/page.tsx` — додано, як і в сусідньому
`MODEL_FILTERS`.

**12. Гендерована фраза в порожньому стані профілю.** `players/[id]/page.tsx` — "Ще не
зіграла/зіграв" → "Ще немає жодного матчу", узгоджено з рештою застосунку.

**13. Немає посилання назад зі сторінок деталей.** `news/[id]`, `tournaments/[id]`, `players/[id]`
— "← Усі новини/турніри/гравці" зверху, той самий текстовий стиль, що й "Усі матчі →" на головній.

### Адмін-панель

**14. Таб-рядок адмінки обрізався на телефоні, "Журнал" був недосяжний.**
`src/components/admin/admin-nav.tsx` — `overflow-x-auto` на самому `<nav>` плюс `shrink-0
whitespace-nowrap` на пунктах: рядок тепер контейнерно прокручується (перевірено програмним
скролом — `scrollWidth` 391 проти `clientWidth` 358, "Журнал" стає повністю видимим), замість
обрізання без жодного натяку на прокрутку.

**15. Список гравців — єдиний в адмінці без пагінації.** `admin/players/page.tsx` перейшов з
`getPlayers()` на `getPlayersPage()` + `SearchInput` (`?q=`) + `LoadMore`, той самий патерн, що й
Турніри/Новини/Користувачі. `getPlayersPage`'s `where` розширено до `OR` за іменем/email/email
акаунту — попередній клієнтський пошук шукав і по email, звузити пошук при переході на сервер
було б регресією. Окремий нюанс: підрахунок "які акаунти вже прив'язані" (для
`LinkPlayerControl`) не може спиратись на пагінований/відфільтрований список — новий
`getLinkedUserIds()` рахує це по всій таблиці незалежно від пагінації сторінки.

**16. Заголовки сортування без `aria-sort`.** `tournaments-table.tsx` (`SortableHead`) —
`aria-sort="ascending"|"descending"|"none"` на `<th>` відповідно до активного стовпця й напрямку.

**17. Перемикачі сіяності/групи в ростері мовчки відкочувались при помилці.**
`tournament-roster.tsx` — `SeedToggle` і `GroupSelect` отримали `toast.error` в `catch`;
`GroupSelect` додатково тепер перевіряє `result?.error` (раніше повернене значення
`setParticipantGroupAction` просто ігнорувалось, і помилка "Некоректний номер групи" губилась).

**18. Кнопка підтвердження видалення учасника без стану очікування.** `tournament-roster.tsx`
(`RemoveParticipantButton`) — `disabled={pending}` + напис "Прибираємо…" на
`AlertDialogAction`, як і решта деструктивних підтверджень у застосунку.

**19. Форма новини не мала жодного з полегшень інших форм.** `news-dialog.tsx` +
`actions/news.ts` — `ActionState` отримав `fieldErrors` (`fieldErrorsFromZod`), поля Заголовок/
Текст — `RequiredMark`, `aria-invalid`, помилка під полем, живі лічильники "N/150"/"N/5000" і
відсутній раніше `maxLength={5000}` на `<Textarea>` тіла новини.

**20. Видалення турніру без підсиленого підтвердження, хоч ризик той самий, що в
рерандомайзера.** `delete-tournament-button.tsx` — той самий набір слова "ВИДАЛИТИ" (сервер:
новий переекспортований `checkCompletedMatchesAcknowledged` з `actions/matches.ts`, той самий
захист другого рівня; клієнт: `completedMatchCount`, рахований зі вже завантажених `matches` на
сторінці турніру, без нового запиту). Підтверджено вручну в браузері на реальному завершеному
турнірі з 15 матчами — діалог показує точну кількість, кнопка "Видалити" заблокована, доки не
введено слово.

**21. Журнал аудиту показував сирі ID гравця замість імені.** `actions/tournaments.ts` —
`removeParticipantAction` (окремий `findUnique` за іменем) і `toggleParticipantSeedAction`
(`include: { player: { select: { name: true } } }` прямо в `update`, без зайвого запиту) тепер
пишуть ім'я гравця в `summary`. Перевірено напряму по БД після реальних дій в браузері: нові
записи — "Позначено сіяним гравця Андрєєв Олександр" замість "...гравця cms37in3h...".

**22. "Прив'язати" активна без обраного акаунту.** `link-player-control.tsx` — `LinkButton`
отримав `disabled` проп, викликається з `selected === ""`.

**23. Select ролі у власному рядку адміна без пояснення.** `user-role-select.tsx` —
`title="Не можна змінити власну роль"` на `SelectTrigger`, коли `disabled` (не під час `pending`).

**24. Списки новин і користувачів без пошуку.** `getNewsPostsPage`/`getUsersPage` отримали
опційний `query` (title-пошук для новин, ім'я/email — для користувачів, той самий `OR`-патерн,
що й гравці); обидві сторінки — `SearchInput` + `?q=` в `LoadMore`-посиланні.

### Верифікація

`npm run lint`, `npx tsc --noEmit`, `npm run test` (262 тести), `npm run build` — усе проходить
чисто. Ручна перевірка в реальному Chromium через Playwright (тестовий адмін-логін):
- мобільний хедер (390px) на головній і в адмінці — без накладання, скріншот до/після;
- admin-nav на 390px — програмний scroll підтверджує контейнерну прокрутку, "Журнал" досяжний;
- `/matches` на 390px — імена пари кожні на своєму рядку, без розриву посеред імені;
- активний пункт навігації жирним на `/matches` (публічна) і `/admin/audit` (адмінка);
- `page.title()` для `/news/[id]`, `/tournaments/[id]`, `/players/[id]` — назва сутності, не
  загальна назва сайту;
- back-link "← Усі новини"/"← Усі гравці" на відповідних сторінках деталей;
- діалог видалення турніру на реальному завершеному турнірі (15 матчів) — попередження з точною
  кількістю, кнопка заблокована без введеного слова "ВИДАЛИТИ";
- новий запис журналу аудиту після реальної дії в UI — ім'я гравця, не CUID (перевірено прямим
  запитом до БД);
- форма новини — зірочки обов'язкових полів і лічильники символів вживу;
- сторінка гравців адмінки — пошук + пагінація замість повного списку.
