# Головна сторінка v2: Тріпл-Спліт на 100vh (Кава / Теніс / Падел)

## Контекст

Другий, незалежний варіант редизайну головної (перший — гілка `redesign/split-screen-v1`,
світлий картковий дизайн; цей — гілка `redesign/triple-split-v2`, темний, за детальним ТЗ
користувача). `/` стає "хабом" клубу: під шапкою сайту — три вертикальні колони на весь екран
(Кава / Теніс / Падел). На hover активна колона розширюється з 33.3% до 50%, дві інші рівномірно
стискаються до 25% кожна. Поточний вміст головної (hero, картки, останні результати, новини)
переїхав на нову сторінку `/tennis`. Додано `/tennis/pricing` (ціни, плейсхолдер) і
`/tennis/coaches` (галерея тренерів, запис лише по телефону), а також мінімальну заглушку
`/coffee`.

Перед реалізацією користувачу показано два інтерактивні Artifact-мокапи (спершу без футера, потім
з ним) на затвердження дизайну — стандартний робочий процес для нетривіальних UI-змін у цьому
проєкті.

## Дизайн

**Точна математика 33/33/33 → 50/25/25.** Tailwind-утиліти не вміють "коли ховериться колона A,
колонки B і C стискаються" в обидва боки DOM-порядку (`peer`/`group-hover` реагують тільки на
наступного сиблінга). Тому логіка — невеликий блок чистого CSS в `globals.css` через сучасний
селектор `:has()` (підтримується всіма актуальними браузерами), активний тільки з `md:` (768px+):
кожна панель `flex: 0 0 33.3333%`, а `.triple-split:has(.split-panel:nth-child(N):hover)` виставляє
`flex-basis: 50%` для N-ї панелі й `25%` для двох інших. На мобільному та ж розмітка, але
`flex-direction: column` — три горизонтальні блоки без hover-логіки, увесь текст і кнопки одразу
видимі.

**Клік по всій колонці Тенісу.** Клік будь-де по колонці → `/tennis`; окрема кнопка "Забронювати
корт" → `/tennis/pricing`. Вкладати `<Link>` в `<Link>` не можна (невалідний HTML). Рішення —
патерн "картка як лінк": фоновий `<Link href="/tennis" className="absolute inset-0 z-10">` +
поверх нього текстовий шар `pointer-events-none` з вищим z-індексом, всередині якого кнопка
`pointer-events-auto`. Кава не клікабельна по всій зоні (тільки кнопка-лінк на `/coffee`, як прямо
вказано в ТЗ), Падел не клікабельний узагалі (кнопка — `<span aria-disabled>` без `href`,
`cursor-not-allowed`). Компонент (`src/components/triple-split.tsx`) — Server Component, жодного
client-side JS не знадобилось.

**Важливий стекінг-нюанс** (спіймали двічі на Artifact-мокапі, поки не дійшли до кореня):
недостатньо дати `z-index` тільки самій кнопці — обгортка тексту теж має власний `position:relative`
+ `z-index`, тобто створює свій stacking context, і z-index кнопки всередині порівнюється лише з
сусідами всередині ЦІЄЇ обгортки, а не з фоновим `<Link>` зовні. Підняти треба ОБГОРТКУ (не тільки
кнопку) вище фонового лінка.

**Full-bleed 100vh.** `<main>` у `layout.tsx` має `max-w-5xl px-4 py-8` — лишається без змін для
решти сайту. Спліт-секція й новий футер на `/` "вириваються" з цього контейнера стандартним
Tailwind-прийомом (`relative left-1/2 right-1/2 -mx-[50vw] w-screen`, плюс `-my-8` щоб прибрати
вертикальний padding). Nav лишається видимим зверху як завжди (без спецкейсів). Сама 3-колонкова
секція — рівно `h-dvh`, три колонки завжди видно без внутрішнього скролу; сторінка в цілому
скролиться нижче — там новий брендований футер (короткий контекст нижче) і вже існуючий сайтовий
`<footer>` як завершальний copyright-рядок.

**Брендований футер (тільки на `/`).** За проханням користувача додати щось на кшталт
yellow-padel.com — але навмисно **інша композиція** (не двоколонковий блок із заголовками, щоб не
було візуальної схожості зі стороннім сайтом): один горизонтальний ряд — мітка SET.club + таглайн
зліва, контакти (адреса · телефон · email — усе ще плейсхолдери) по центру, єдина іконка Instagram
(реальний профіль `instagram.com/setclub.ua`) справа.
Без "Публічна оферта" — користувач сказав, що не потрібно.

**Контент-уточнення від користувача:** у клубі лише ґрунтові корти (одне покриття) — у текстах
скрізь "ґрунтові корти", не абстрактне "професійні".

**Фонові фото** — Unsplash-плейсхолдери (кав'ярня/теніс/будівництво для панелей,
портрети для тренерів), перевірені вручну (завантажені й переглянуті) перед використанням, щоб не
було нерелевантних чи непрацюючих зображень. `images.unsplash.com` додано в
`next.config.ts` (`images.remotePatterns` + CSP `img-src`).

## Відоме обмеження автоматизованого тестування (не поведінка продукту)

Під час перевірки Playwright-скриптами клік мишею по фоновому `<Link>` Тенісу (великий, повністю
прозорий, `position: absolute`) періодично не тригерив навігацію в headless Chromium — але:
programmatic `el.click()`, клавіатурна активація (`Tab` + `Enter`) і пряма навігація на `/tennis`
завжди спрацьовували коректно, а сам патерн (розтягнутий прозорий `<Link>` поверх картки) —
стандартний, широко вживаний на вебі. Схоже на флакі headless-автоматизації навколо
`position: absolute` елементів (можливо, у поєднанні з CSS-переходом `flex-basis` на предку), а
не на реальний дефект — реальні користувачі клікають повільніше й без цієї специфічної гонки.
Якщо колись підтвердиться як реальна проблема (скарги користувачів) — вартий розгляду альтернативний
підхід без `position: absolute` для цього шару.

## Обсяг цієї ітерації vs майбутнє

**Зроблено:** спліт-секція, брендований футер, `/tennis` (переїхав контент), `/tennis/pricing`,
`/tennis/coaches`, мінімальна заглушка `/coffee`.

**Свідомо не зроблено (майбутні кроки):** повноцінна фіча "Кав'ярня" (меню, фото, можливо
замовлення), реальна сторінка Паделу (коли добудують корт), реальні контактні дані/ціни/фото
замість плейсхолдерів.
